### 실행 방법

```bash
# 백엔드
cd backend && python manage.py test

# 프론트엔드 단위 테스트
cd frontend && npm run test

# E2E: 서버를 직접 띄울 필요 없음 (전용 백엔드 8001, 프론트엔드 5174를 Playwright가 시작)

cd frontend && npm run e2e:local    # Firefox가 실행되지 않는 PC용

# 스크립트
node --test scripts/
```

WebKit과 iPhone 13 에뮬레이션에서만 실패하는 테스트는 없었고, 코드를 고칠 필요가 없었습니다.

**Firefox 미검증 사유**: 이 PC에서 Playwright용 Firefox 159.0이 실행되지 않았습니다. 테스트 36건 모두 브라우저를 띄우는 단계에서 `browserType.launch: spawn UNKNOWN`으로 끝났고, 앱 코드는 한 줄도 실행되지 않았습니다. Windows 이벤트 로그에는 `firefox.exe`의 활성화 컨텍스트를 만들지 못했다(종속 어셈블리 `mozglue`를 찾을 수 없음)는 SideBySide 오류가 남았습니다. `npx playwright install --force firefox`로 다시 받아도 같았습니다. `mozglue.dll` 파일은 설치 폴더에 있고 Smart App Control은 꺼져 있어, 원인은 이 Playwright Firefox 빌드와 이 PC의 Windows 환경 사이의 문제로 보이며 더 추적하지 않았습니다. Firefox 프로젝트 설정은 `playwright.config.js`에 남겨 두었으므로 Firefox가 실행되는 PC에서는 `npx playwright test --project=firefox`로 검증할 수 있습니다.

iPhone 13은 에뮬레이션입니다. 실제 기기에서의 확인은 `docs/MOBILE_TEST.md`의 점검표로 진행합니다.

## 6. 알려진 제한 사항

실제로 해결되지 않은 항목만 남겼습니다.

- **Firefox 미검증.** 이 PC에서 Playwright용 Firefox가 실행되지 않습니다(4.5). Firefox가 실행되는 PC에서 `npx playwright test --project=firefox`를 실행해야 합니다.
- **실제 휴대폰 미검증.** iPhone 13 항목은 에뮬레이션입니다. 휴대폰 접속 스크립트(`dev-lan`)도 이 PC에서 컴퓨터 자신이 로컬 네트워크 IP로 접속하는 방식으로만 확인했고, 실제 휴대폰으로는 접속해 보지 않았습니다. `docs/MOBILE_TEST.md`의 점검표는 아직 한 건도 채워지지 않았습니다.
- **번역은 AI 검수이며 사람이 확인하지 않았습니다.** 운동 이름 132개와 시연용 운동 11개의 단계 번역이 해당하며, 원어민 또는 트레이너의 확인이 필요합니다. `reviewed` 필드는 모두 `false`입니다.
- **동작 단계 번역이 없는 운동이 많습니다.** 시연용 11개를 제외한 121개는 중국어·한국어 화면에서 일반 연습 안내와 영어 원문을 표시합니다.
- **Windows 11에서만 실행했습니다.** `setup.sh`와 `dev-lan.sh`는 Windows의 Git Bash에서만 실행했고, macOS와 Linux에서는 실행해 보지 않았습니다. 백엔드 테스트와 단위 테스트도 Windows에서만 돌렸습니다.
